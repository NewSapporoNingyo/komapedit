# AI 코딩 도구로 komapedit 개발하기

[개발자 가이드](dev_ko.md) · [AI 도구용 저장소 규칙](../AGENTS.md) · [개발 진행 상황](../TODO.md)

이 가이드는 AI 코딩 도구로 komapedit를 개발하는 사람을 대상으로 합니다. 작업을 설명하고, 적절한 작업 절차를 선택하고, 변경과 검증 결과를 검토하는 방법을 다룹니다.

관련 기능과 기본 C++, Windows 빌드 환경을 파악하고 diff와 테스트 결과를 읽을 수 있으면 AI의 해결책을 평가하고 제품 동작과 수용 기준을 결정하기 쉽습니다.

저장소는 AI 도구용 [`AGENTS.md`](../AGENTS.md)와 [프로젝트 스킬](../.agents/skills)을 제공합니다. 프롬프트에서 관련 스킬을 직접 지정할 수 있습니다. [프로젝트 메모리](../.agents/memories/INDEX.md)에서 이전 결정의 배경을 확인하세요. 현재 구현은 소스와 테스트를 기준으로 확인하며, 개발 진행 상황은 [`TODO.md`](../TODO.md)에 기록합니다. 프로젝트에 한정된 스킬과 교훈은 `.agents`에 두고, 여러 프로젝트에서 사용하는 지침은 사용자 수준에 둡니다.

## 작업을 구체적으로 설명하기

구체적인 동작과 확인할 수 있는 결과를 적습니다.

- 관찰한 동작 또는 원하는 기능
- 재현 단계와 관련 입력, 로그, 스크린샷 또는 노선 파일
- 변경 범위와 유지해야 하는 사용 방식, 호환성, 성능
- 기대 결과와 수용 기준
- 빌드 및 테스트 범위, 검증할 노선, 수동 GUI 확인 방식

예를 들어 느려지는 문제를 다룰 때는 성능 개선이라는 포괄적인 요청보다 느려진 작업, 노선 규모, 빌드 유형, 소요 시간을 적는 편이 진단과 검증에 도움이 됩니다. 파일 형식, 호환성 마이그레이션, 공개 ABI 또는 새 종속성에 관한 결정이 필요하면 먼저 읽기 전용 조사를 요청하고 구현 전에 계획을 정할 수 있습니다.

## 작업 절차 선택하기

저장소의 기본 작업 절차는 일반 개발, 버그 수정, 코드 유지보수, 문서 작성입니다. 스킬을 명시적으로 호출할 수 있는 클라이언트에서는 아래 프롬프트를 사용할 수 있습니다. 다른 클라이언트에서는 자연어로 작업을 설명하고 스킬의 경로를 지정합니다. 필요에 따라 원본 편집, 표, 2D/3D 미리 보기, 설정, 다국어 UI, 검증에 맞는 전문 스킬을 함께 사용합니다.

### 일반 개발

[`komapedit-develop`](../.agents/skills/komapedit-develop/SKILL.md)을 사용해 기능을 추가하거나 동작을 바꿉니다.

```text
$komapedit-develop을 사용하세요.
요청: [기능, 영향을 받는 작업 절차, 제약 및 수용 기준]
유지할 항목: [호환성, 성능, 조작 방식, 파일 또는 API]
검증: [Debug 빌드, 관련 CTest/headless 검사, 검증 노선 및 수동 GUI 확인]
```

일반 개발에서는 Debug 빌드를 사용합니다. 배포 패키징, 런타임 종속성 또는 최적화 관련 작업은 Release에서도 확인합니다. 명령은 [개발자 가이드](dev_ko.md)를 참조하세요.

### 버그 수정

[`komapedit-fix`](../.agents/skills/komapedit-fix/SKILL.md)는 재현과 원인 파악부터 시작해 해당 동작을 담당하는 모듈을 수정합니다. 원인이 불분명하면 읽기 전용 진단을 먼저 요청할 수 있습니다. 원래 재현 단계와 관련 회귀 테스트로 수정 결과를 확인합니다.

```text
$komapedit-fix를 사용하세요.
관찰 내용: [증상, 로그, 빌드 유형, 노선 또는 입력, 재현 단계]
기대 결과: [올바른 동작]
범위: [진단 또는 진단과 수정]
검증: [원래 재현 절차와 관련 Debug/Release/headless 검사]
```

### 코드 유지보수(slop-fix)

[`komapedit-slop-fix`](../.agents/skills/komapedit-slop-fix/SKILL.md)는 중복 로직, 사용하지 않는 상태, 캐시 오류, 잠재적 충돌 등 근거가 있는 품질 문제를 다룹니다. 먼저 조사한 뒤 기존 동작과 ABI를 유지하며 확인된 문제를 수정합니다.

```text
$komapedit-slop-fix를 사용하세요.
범위: [특정 하위 시스템, 변경 파일 또는 전체 프로젝트]
먼저 읽기 전용으로 조사해 문제별 근거, 영향, 수정안, 검증 방법을 기록한 뒤 확인된 문제를 수정하세요.
기존 동작과 ABI를 유지하세요.
검증: 엄격한 경고가 활성화된 Debug, 등록된 CTest, 관련 headless 검사. 성능 작업은 같은 조건에서 측정한 전후 데이터를 포함하세요.
```

조사 결과에 따라 현재 코드를 유지할 수 있습니다.

### 문서 작성

[`komapedit-write-docs`](../.agents/skills/komapedit-write-docs/SKILL.md)는 문서를 개정하거나 코드 변경을 문서에 반영할 때 사용합니다. 대상 독자, 파일, 언어를 지정하고 현재 소스와 테스트, 빌드 스크립트를 근거로 삼습니다.

```text
$komapedit-write-docs를 사용하세요.
내용 및 대상: [설명할 현재 동작 또는 작업 절차와 대상 독자]
파일과 언어: [문서 경로 및 동기화할 언어판]
범위: 문서 변경.
```

[`komapedit-doc-sync-validation`](../.agents/skills/komapedit-doc-sync-validation/SKILL.md)은 범위, 언어판 간 의미, 인코딩, 링크, 표를 검증합니다. 소스 구성과 검증 명령은 현재 파일, CMake 대상, 명령줄 진입점과 대조합니다.

### BVE 형식과 원본 편집 작업

BVE 형식에 관한 개발과 수정에는 [`komapedit-bve-format-compliance`](../.agents/skills/komapedit-bve-format-compliance/SKILL.md)를 사용합니다. [공식 자료 기준표](../.agents/skills/komapedit-bve-format-compliance/references/official-bve-format-baseline.md)의 Map, Structure List, Signal Aspects List, Sound List, 타 열차 및 Scenario 형식에 대한 읽기, 파싱, 검증, 타입 표현, 편집, 생성, 직렬화, 원본 쓰기를 다룹니다.

구현 전에 공식 페이지를 바탕으로 현재 구문, 구형 별칭, 프로젝트 호환 형식, 미지원 형식을 나눈 준수 표를 작성합니다. 공식 페이지는 날짜와 함께 로컬에 캐시합니다. 타임스탬프가 유효하지 않거나 30일이 지났으면 전체 캐시를 갱신합니다. 공식 사양, 요구 사항, 구현 사이의 동작 차이는 사용자가 처리 방향을 결정합니다.

```text
$komapedit-bve-format-compliance를 $komapedit-develop 또는 $komapedit-fix와 함께 사용하세요.
형식과 요소: [영향을 받는 파일, 구문, 목록 행, 섹션 또는 키]
작업: [읽기 / 검증 / 편집 / 생성 / 직렬화 / 원본 쓰기]
수용 기준: [공식 시그니처와 의미, 저장 및 다시 불러오기, 유효 및 무효 입력, 원본 보존]
```

원본 편집에는 [`komapedit-source-backed-editing`](../.agents/skills/komapedit-source-backed-editing/SKILL.md)을 사용합니다. Station, Structure, Signal, Sound, Sound3D 목록의 가져오기·교체·생성, 빈 목록에 첫 행 추가 또는 행 삽입을 다룰 때는 [`komapedit-resource-list-source-editing`](../.agents/skills/komapedit-resource-list-source-editing/SKILL.md)도 사용해 형식, 편집, 저장 절차를 함께 확인합니다.

## Pi Agent와 협업하기

Pi Agent는 간결한 코딩 에이전트입니다. Pi에 구현을 맡기려면 Pi에 프롬프트를 직접 입력하거나, 다른 코딩 에이전트에 Pi 실행을 명시적으로 요청하거나, [`$collaborate-with-pi`](../.agents/skills/collaborate-with-pi/SKILL.md)를 호출합니다.

조정 에이전트는 저장소를 조사하고 개발 계획을 `pi-prompts_local.txt`에 작성한 뒤 표시되는 Windows Terminal에서 `pi-agent-here(local).bat`로 Pi를 시작합니다. Pi는 주요 구현과 관련 테스트, 문서 수정을 맡습니다. 조정 에이전트는 진행 상황을 확인하고 완료 후 실제 diff를 검토하며 주요 검사를 다시 실행하고 필요한 수정을 조율합니다.

Pi 세션에서 문제가 발생하면 협업을 종료하고 완료한 변경과 남은 작업을 보고합니다. 이후 절차는 사용자가 결정합니다. 실행, 상태 확인, 수정 절차는 스킬을 참조하세요.

## 변경 사항 검토하기

실제 diff를 작업 범위와 수용 기준에 대조한 뒤 관련 검사를 선택합니다.

- **기능과 UI**를 확인하려면 영향을 받는 작업을 다시 수행합니다. 영어, 중국어 간체, 중국어 번체(대만), 중국어 번체(홍콩), 일본어, 한국어의 문구와 선택 상태, 마커, 표와 2D/3D 보기 사이 이동, 설정 저장을 점검합니다.
- **노선 편집**은 Include, 원래 식, 구문 순서, 인코딩, BOM, 줄바꿈 보존을 확인하고 저장과 다시 불러오기 후 내용을 비교합니다.
- **모듈 인터페이스**는 DLL 변경 시 버전이 있는 타입 C ABI, 구조체 크기, 데이터 소유권, 짝이 되는 해제 함수와 예외 처리를 확인합니다.
- **성능**은 같은 노선, 매개변수, 빌드 유형, 작업량으로 전후를 비교합니다. 반복 I/O, 프레임마다 수행하는 재구축, 캐시 무효화도 점검합니다.
- **종속성과 배포**는 Windows 및 도구 모음 호환성, 라이선스와 고지, 런타임 DLL 배치를 확인합니다.

맵과 리소스 목록에서 `적용`은 메모리 작업 사본과 미리 보기를 갱신하고, `저장`은 파일에 변경을 기록합니다. `되돌리기`는 대기 중인 변경을 폐기하며, `다시 불러오기`는 저장하지 않은 변경이 있으면 확인을 거친 뒤 디스크에서 읽습니다. 리소스 목록 초안은 해당 표에서 먼저 적용합니다. 시나리오 초안은 `저장`에서 바로 기록합니다. 이 순서에 맞춰 편집 전체 흐름을 검증합니다.

수용 보고서에는 실제 실행한 명령과 결과, 확인된 실패를 적고 빌드, CTest, headless, 수동 GUI 확인을 구분합니다. 실제 인터페이스에서 렌더링, 메뉴, 대화 상자, 끌기를 확인합니다. 작업이 범위를 벗어나거나 같은 작업에서 계속 실패하거나 보고와 근거가 다르면 작업을 잠시 멈추고 현재 diff를 확인한 뒤 목표를 분명히 할 수 있습니다.

## S4 2D画布自轨道线形编辑

**主要位置：** 2D 模式与网格控件、画布交互和标记缓存、类型化快照接收、共享自轨道几何计算、编辑账本与距离位置选择流程。

**现有基础：** 2D 顶部集中提供“移动 / 测量”模式和三个网格选项；画布缓存已提供曲线阴影、半径文字、曲线及坡度标记。检查器与类型化编辑批次已支持对应距离及参数修改，现有应用流程负责完整重解析和线形刷新。

### 交付范围与交互

1. 在顶部增加“编辑”单选项，与“移动 / 测量”互斥。全局编辑模式关闭时，“编辑”置灰；关闭全局编辑模式后恢复进入编辑前的导航模式。在三个网格选项右侧增加“应用”按钮，有可应用的画布草稿时启用，操作期间沿用现有忙碌状态控制。可见文本同步六种界面语言。
2. 支持沿自轨道前后拖动曲线端点、缓和曲线端点和坡度变化点。将鼠标投影到轨道折线求取里程，以手势开始时的里程为基准按 5m 增量吸附，保留原有非整 5m 的里程余数；拖动时在鼠标右侧显示当前里程小标签，端点和线形随候选值更新。里程有效范围、语句顺序和缓和曲线配对关系采用现有编辑规则。
3. 命中曲线阴影区时，每格滚轮使有符号半径增减 5m，向上增加、向下减少。正值为右曲线，0 为直线，负值为左曲线；半径文字与线形预览同步更新。当前滚轮操作的目标在半径变为 0 后继续保留，支持接着滚动。阴影命中的滚轮输入用于半径编辑，画布其他区域沿用现有缩放和旋转操作。
4. 拖动和滚轮操作积累为画布参数草稿，点击“应用”后更新内存工作副本，保存提交工作副本到磁盘。存在未应用的画布草稿时，保存提示先在 2D 窗口应用。切换移动、测量和编辑模式时保留草稿，Esc 取消当前拖动，还原清除画布草稿并执行现有还原流程。关闭编辑模式、重载、切换文件和退出时，将画布草稿纳入现有未保存状态处理。

首批鼠标编辑作用于 2D 平面画布中的自轨道；纵断面图和半径图沿用当前交互，应用后同步正式数据。“编辑”作为当前会话的操作模式，启动时恢复已保存的移动或测量模式。即时预览更新自轨道、相关端点、阴影和标签，正式应用后通过现有刷新链更新关联视图。

### 实施步骤

1. **建立编辑目标关联。** 在快照接收及缓存构建时，为端点、曲线区段和派生轨道事件绑定稳定编辑身份。缓和曲线端点复用共享过渡链关联，已配对端点通过对应主语句编辑；孤立缓和起点维持现有只读规则。
2. **增加画布草稿和输入处理。** 草稿按编辑身份记录距离、半径等变化字段。拖动期间固定本次手势的参考轨道及局部搜索范围，保证线形变化后鼠标投影连续；保留现有测量、背景图对齐和标记导航的输入分工。
3. **复用几何计算生成即时预览。** 将现有自轨道几何计算整理为共享的内部 C++ 模块，由正式几何生成和 2D 参数预览共同调用。预览输入使用已求值轨道事件及参数草稿，源码解析继续由地图加载组件负责；公共 C ABI 沿用现有接口。
4. **控制预览成本。** 仅在吸附后的候选值改变时发起计算，合并连续输入，由后台任务处理最新候选。复用最早受影响边界之前的轨道前缀，重算其后的受影响线形，绘制继续使用可视范围裁剪。缓存由模型版本、草稿版本和采样参数确定，过期结果按版本丢弃。
5. **接入正式应用。** 将画布草稿按字段合并到现有待应用编辑集合，在绘制结束后执行类型化批次。完整重解析成功后统一刷新表格、2D 和 3D；失败时保留草稿及现有工作副本，并进入既有诊断或距离位置选择流程。
6. **保持源码语义。** 覆盖现有 `Curve.Begin / BeginCircular / Change / End / Interpolate` 和 `Gradient.Begin / BeginConst / End / Interpolate` 端点。半径滚动作用于命中区段对应的显式半径字段；保留原语句形式、其他参数、表达式、注释、编码及 Include 来源。实施时按官方 Map 缓存建立本阶段合规矩阵。

### 验收与完成条件

- 检查模式互斥和禁用状态、三类端点双向拖动、非整 5m 初值、重叠标记选择、正负半径及经过 0 后继续滚动。
- 检查预览、应用结果和保存重开后的几何一致；覆盖连续应用、取消、还原、Include、表达式里程、距离歧义和应用失败后的草稿保留。
- 运行类型化编辑、快照、坡度投影和六语言相关契约，扩展现有自轨道编辑与 2D 无界面验证。
- 使用相同线路、采样参数和 Debug 构建比较静止、连续拖动及滚轮操作，记录预览延迟、帧耗时及计算次数，沿用现有 2D 帧预算；实际界面验收命中范围、文字位置和连续操作反馈。

**完成条件：** 三类端点可按 5m 增量沿自轨道拖动，曲线阴影区的滚轮按有符号半径每格增减 5m；里程标签、半径文字与线形预览同步更新。应用后的工作副本、关联视图和保存重开结果一致，草稿生命周期、六语言和性能验收通过。

**主要位置：** 项目元数据读写、地图注释解析、源码身份与保存协调。

1. 确定项目根、`kme.json` 的结构与版本、路径基准、保存时机和并发规则，明确文件类型、用途、语句组合及预设的存储职责。
2. 确定 `//--kme--` 元素标记的具体语法、行位置、物理语句与引用实例的归属，以及复制、删除和重复标识的处理规则。标记使用官方地图注释形式。
3. 将跨会话标识与工作副本编辑身份建立显式映射，接通元数据与源码修改的预览、保存及重载。
4. 验证项目移动、外部改动、重复引用、复制成员、删除目标和失联关联，并检查普通注释及字符串中的相似文本。

**完成条件：** 文件用途和组合信息可保存重开；带标记元素在约定操作后保持正确关联，关联冲突有明确诊断，BVE 按普通注释处理源内标记。

## S8 资源列表注释

**主要位置：** 五类资源列表解析、类型化快照、快照接收与表格缓存。

1. 确定 `#--kme--comment:"content"` 的内容转义、空值与重复标记规则，明确同行定义、信号主行和辉光行的注释归属。
2. 在地图加载组件解析原始行时提取注释，通过类型化字段传递，在表格缓存构建时附到对应资源键。
3. 在键单元格悬停时显示缓存内容，保留列表原始字段、注释和源码顺序。
4. 覆盖车站、布景、信号、声音、三维声音列表，以及中文、引号、逗号、反斜杠、无效标记、编码和重载。

**完成条件：** 五类列表的有效注释显示在对应键上，信号主行与辉光行归属准确；重复绘制表格复用注释缓存。

<a id="s9"></a>

## S9 多语句预设组

**前置：** S7 的元数据存储契约。

**主要位置：** 预设数据、组合向导、结构化编辑批次与资源键选择。

1. 确定首批支持的语句类型、参数和资源键映射，先交付同里程语句组。将预设副本与持续关联源码成员的组合分别定义。
2. 将成员类型、结构化字段、成员顺序和参数映射保存到 `kme.json`，实现采集、命名、选择和应用。
3. 复用现有组合模板及插入链，一次应用形成完整编辑批次，生成普通 BVE 地图语句。
4. 验证资源缺失、键冲突、重复应用、成员失败、整组还原与保存重开，并在重解析后核对全部成员和非目标语义。

**完成条件：** 约定类型的多语句预设可保存、选择并一次应用；所有成员共同成功或回滚，生成语句可继续通过现有检查器编辑。

<a id="s10"></a>

## S10 参数表达式

**主要位置：** 解析器求值、编辑字段契约、目标位置变量环境与参数输入控件。

1. 列出可输入表达式的字段，分别确定数值参数、距离、字符串和键的输入规则，以及表达式字段被操纵器修改时的交互。
2. 在地图加载组件中使用目标语句或插入位置的实际变量环境求值，复用官方运算符、变量与数学函数规则。
3. 将输入原式与求值结果沿类型化编辑链传递，按字段校验类型、有限值和范围；写回原始表达式，并保留其他参数的源码。
4. 验证变量重赋值前后、嵌套与重复引用、未定义变量、无效表达式、函数参数、随机求值重放及保存重开。

**完成条件：** 约定字段可用变量、运算和数学函数设置参数；输入原式、预览值、重解析值及保存重开结果一致，操纵器修改遵循已确定的表达式处理规则。

<a id="s11"></a>

## S11 变量编辑与新建

**前置：** S10 的表达式输入与目标位置求值。

**主要位置：** 变量赋值源码记录、类型化赋值身份、语义比较、变量表格与插入链。

1. 确定数值与字符串赋值、变量重命名的交付范围，以及变量影响距离、资源键、路径和引用文件时的处理规则。
2. 为每次具体赋值记录源码位置、解析顺序和编辑身份，建立变更后的预期影响集合，覆盖后续读取、再次赋值和引用环境。
3. 实现已有赋值编辑，再实现指定位置新建赋值。完整重解析证明集合内的预期变化，集合外沿用现有语义与变量环境校验。
4. 验证同名多次赋值、定义先后、空文件、未使用变量、重复引用、随机重放、编码、连续应用、还原和保存重开。

**完成条件：** 变量编辑和新建均作用于确定的赋值位置；下游变化符合预期影响集合，非目标区域与磁盘并发保护保持有效。

<a id="s12"></a>

## S12 跨里程相对位置组

**前置：** S9 的预设与批次；持久关联复用 S7，表达式基准复用 S10。

**主要位置：** 预设成员模型、距离解析与插入、共享链关联、整组预览。

1. 为组合确定参考成员、相对里程、成员顺序、资源映射，以及单文件或跨文件、一次性模板或持续关联的覆盖范围。
2. 先完成固定数值偏移的实例化，再扩展参考位置变化、整组复制和平移；表达式位置按各成员所在的变量环境验证。
3. 使用完整批次处理成员距离和曲线、坡度、重复布景链关系，确定参考成员删除或替换后的组状态。
4. 验证正、负、零偏移，同里程先后，文件末尾、重复引用、链边界、环境改变、任一成员失败及保存重开。

**完成条件：** 组成员可按参考里程准确实例化、复制和平移；语句顺序与链关系正确，持久关联稳定，整组应用和还原结果完整。

<a id="s13"></a>

## S13 纵曲线、缓和曲线与超高计算

**主要位置：** 新增工程计算逻辑、现有曲线与坡度向导、共享取样和几何验证。

1. 确定首批规范及版本、线路用途、设计速度来源、单位、取整规则和适用条件，为每类计算准备独立例题。
2. 根据前后坡度和规范所需设计输入计算纵曲线长度，显示控制条件，处理坡变点位置及相邻过渡关系。
3. 根据半径、轨距、限速和规范附加条件计算缓和曲线长度与超高，说明控制约束和推荐值，并处理方向与无解情况。
4. 将结果回填现有向导，经结构化批次生成普通语句，重解析并验证几何；覆盖等坡、凸凹变坡、正负曲线、直线、不同轨距和区间重叠。

**完成条件：** 两类计算均能给出有规范依据、输入和计算过程的结果，独立例题通过；回填后生成的语句和几何符合所选设计条件。

## S14 单开与 Y 形道岔自动计算

**主要位置：** 道岔约束求解、他轨道几何、新建向导与结构化批次。

1. 确定中心线布置或完整工程道岔的交付范围，明确前后里程、相对位置、切向、曲率、设计参数和轨道姿态的输入约束。
2. 建立单开与 Y 形道岔求解、可行性判断和多解选择规则，显示输入条件、几何预览及计算误差。
3. 将选定解转换为普通 BVE 自轨道与他轨道语句，以完整批次预览和应用。
4. 使用独立样例检查端点位置、切向连续性与曲率约束，覆盖对称 Y 形、反向、零长度、无解和多解；对生成源码重新解析并取样验证。

**完成条件：** 单开和 Y 形道岔均可按约定输入生成；独立求解与重解析几何满足约定误差，失败时保留原编辑状态。

## S15 线路发行版导出

**主要位置：** 新增线路导出流程、源码与引用数据、资源依赖收集、输出报告。

本阶段交付编辑器内的线路发行功能：向独立目录输出可分发的线路文件、资源和报告。

1. 确定从磁盘还是已应用工作副本导出，明确场景、车辆、地图、模型及声音的覆盖范围，以及随机求值、缺失资源和“实际使用”的判断规则。
2. 先交付只读依赖清单与预检，再交付保守复制、相对路径处理及报告。依赖收集覆盖模型纹理、信号辉光、车站音效、他列车和共享资源。
3. 实现 `Include` 展开，保持文件局部里程、变量执行顺序和相对路径语义；随后增加距离与变量表达式常量化、实际使用资源筛选。
4. 检查输入输出路径关系和文件名冲突，向独立输出位置生成产物；验证开发文件前后内容一致，并比较语句值、变量结果、引用、轨道几何和资源闭包。
5. 将产物移离开发目录，分别验证本项目加载和 BVE 运行，报告转换内容、资源来源、诊断和验证结果。

**完成条件：** 导出选项产生语义一致的线路；展开、常量化和资源筛选分别通过验证，产物脱离原目录仍可加载，开发目录保持原内容。

## S16 多地区工程规范检查

**主要位置：** 版本化规范规则、工程实体与补充标注、共享取样、检查报告与定位。

1. 确定日本、中国和欧洲地区的具体标准、版本、适用线路及首批条文，以一套规范完成验证后扩展多种预设。
2. 明确道岔、曲线区间、到发线、站台和股道的工程实体及所需输入；通过 S7 的元数据与标记保存补充信息。
3. 先实现输入充分的半径和明确区间股道间距检查，再覆盖道岔、曲线间隔、到发线与站台长度，并检查区间最不利值。
4. 为每条规则提供通过、违反、临界、信息不足和不适用样例。报告规范条文、适用条件、输入来源、计算值、阈值和地图定位。

**完成条件：** 约定地区、版本和检查项目均有独立样例；结论能够追溯到规范与输入，补充信息不足时输出对应状态，报告可定位到相关元素和区间。

## 阶段通用验收与进度维护

1. BVE 文件读取、编辑、创建、生成或写回实施前，按[格式合规流程](../.agents/skills/komapedit-bve-format-compliance/SKILL.md)核对有效的官方页面缓存，并为本阶段建立合规矩阵。工程规则逐项记录规范版本、适用条件和独立计算样例。
2. 公共类型化接口增加字段或对象时，明确版本和结构大小，同步组件、调用方、所有权说明与契约验证。
3. 地图编辑保持应用只更新工作副本、保存提交、还原丢弃待保存修改、重载读取磁盘的操作分工。覆盖编码、字节序标记、换行、注释、引用、解析顺序、连续应用、源哈希和非目标语义。外部文档按各阶段确定的保存契约验收。
4. 用户可见文本同步六种界面语言；表格、标记和场景在输入改变时更新缓存。2D 编辑、三维操作、工作区和新向导完成对应的实际界面与视觉验收。
5. 按[调试与无界面验证流程](../.agents/skills/komapedit-debug-headless-validation/SKILL.md)选择证据：正常代码实现先用 `build_dev.bat` 构建，再运行相关契约和显式无界面验证。新增行为补充针对性验证；发布构建用于发行打包、依赖布局或优化相关任务。
6. 每项完成后同步 [TODO.md](../TODO.md)、本计划与[完成事项归档](TODO_done.md)，按文档所有权更新使用说明和开发指南。记录已完成的自动验证与手动验收；有限子集按自己的交付范围记录。
